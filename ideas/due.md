# `*[due: YYYY-MM-DD]` — дедлайны и напоминания

> Паттерн: маркер → препроцессор → LLM (тот же, что у `[hide]`/`[archive]`).
> Статус: актуализировано 2026-08-01, расширено и дополнено.

## Суть
Препроцессор парсит `*[due: 2026-08-08]` в поле `MindNode.due_date`, подсвечивает
просроченные и приближающиеся узлы в outline, а агент при следующем ходе сам
напоминает о сроках. Проактивность без планировщика — просто маркер + проверка
при чтении diff.

## Синтаксис
- `*[due: YYYY-MM-DD] Текст` — дедлайн на дату
- `*[due: 2026-08-08 18:00] Текст` — дедлайн с временем (опционально)
- `*[due: +3d] Текст` — относительный срок; препроцессор резолвит в абсолют при создании узла
- `*[due: 2026-08-08][x] Текст` — комбинация с чекбоксами `[ ]`/`[x]`: закрытая задача не «горит»
- `*[due: 2026-08-08][hide] Текст` — скрытая ветка с дедлайном не напоминает (если нет `*[due-alert: on]`)

## Статусы узла (вычисляет препроцессор при каждом diff, LLM не вызывается)
| Статус | Условие | Иконка в outline |
|--------|---------|------------------|
| `overdue` | сегодня > due | 🔴 ⏰ |
| `due_today` | сегодня == due | 🟠 ⏳ |
| `soon` | due − сегодня ≤ 3 дней | 🟡 📅 |
| `open` | иначе | 📅 без акцента |
| `done` | есть `[x]` | ✅ без акцента |

## Реализация
### 1. tree_engine.py (препроцессор)
- Расширить разбор маркеров `\[([a-z]+)(?::\s*([^\]]+))?\]` (уже есть для `[hide]`, `[archive]`)
  → извлекать `due`, `due-alert`; хранить `MindNode.due_date: str | None`
- Рендер outline: подставлять иконку статуса перед контентом узла
- `MindNode.overdue_days: int` — вычисляемое поле при сериализации в `.graph.json`
- Опционально: сортировка детей по due (флаг `sort: due` на узле или глобальная настройка)

### 2. agent.py (LLM)
- Новый инструмент `due_report()`: список просроченных/приближающихся узлов
  (ID, срок, дней до/после, текст)
- Хук перед каждым ходом: есть overdue → агент начинает ответ с напоминания
- Антиспам: про `soon` напоминать не чаще 1 раза в день — поле `last_reminded: date`
  на узле обновляет препроцессор, а не LLM

### 3. watcher.py / diff
- Проверка сроков при чтении diff — cron/планировщик не нужен, срабатывает на любое изменение файла
- Препроцессор обновляет `last_reminded`, статусы и иконки без вызова LLM

## UX-сценарии
1. `*[due: 2026-08-01] Отчёт по спринту` — сегодня 02.08 → 🔴; агент: «Отчёт по спринту просрочен на 1 день»
2. `*[due: 2026-08-04] Подготовить демо` — через 3 дня → 🟡; агент упоминает в сводке
3. `*[due: +1d] Проверить PR` — относительный срок, резолвится препроцессором в абсолют
4. `*[due: 2026-08-10][ ] Созвон с командой` — открытая задача, дедлайн виден в outline
5. `*[due: 2026-08-10][x] Созвон` — закрыто → ✅, напоминаний нет

## Edge cases
- Дата в прошлом при создании → сразу `overdue`, но не блокирует ход LLM
- Без времени — конец дня (23:59)
- Часовой пояс: хранить дату локально, сравнивать с `date.today()`
- `due` + `[archive]`: архивные ветки не напоминают (дерево детачено)
- Относительные сроки резолвить один раз в абсолютную дату при создании узла

## Тесты (дополнить tests/test_tree_engine.py)
- Парсинг `due`: с временем / без / относительный / невалидный
- Статусы: overdue, due_today, soon, open, done
- Рендер иконок в outline
- Комбинации `[due]` + `[x]` / `[hide]` / `[archive]`
- `last_reminded` не влияет на статус

## Метрики успеха
- Ноль новых зависимостей (никаких планировщиков/cron)
- Проверка срока < 1 мс на diff
- 100% операций статусов/иконок без вызова LLM
