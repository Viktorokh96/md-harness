# Проблема: знания о системе — «распределённый мозг»

| Кто | Сталкивается с чем |
|---|---|
| Заказчик (разработчик стороннего модуля) | Не знает, где искать: API? доменные правила расчёта ТП? примеры? |
| Внутренний разработчик | Ищет по докам, чатам, коду — то же знание переспрашивает у коллег |

**Знание о системе лежит в трёх местах сразу** (это и есть «распределённый мозг»):
- Документация, ADR, спецификации → RAG база знаний
- Код 30+ репозиториев → AST-граф (code-review-graph), не текстовый grep
- Живые изменения → GitLab: MR, пайплайны, коммиты, диффы

**Примеры реальных вопросов из системы:**
- «Какой endpoint отвечает за X?» → code_agent (граф кода)
- «Как это описано в ADR?» → rag_agent (база знаний)
- «Что изменилось в MR #123?» → gitlab_agent (GitLab)

**Ответ всегда структурирован**: Ответ / Источники / Уверенность,
с иерархией доверия «код > RAG > история чата» — код авторитетнее документа.

**Сейчас:** человек-эксперт как «живая документация» — медленно, дорого, узкое место.
**С помощником:** экспертное знание доступно в момент вопроса, 24/7, локально.
