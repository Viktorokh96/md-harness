# Почему OpenAI Agents SDK (а не LangChain / CrewAI)

**Три критерия выбора — рамка любого ответа:**

| Критерий | Что значит | Как закрыто в нашем коде |
|---|---|---|
| Тонкий слой абстракций | Контроль у нас, а не у фреймворка | `Agent` + `Runner.run()` + `RunHooks` — нет цепочек/графов поверх |
| Явная маршрутизация | Субагент как инструмент, а не «магия» | `agent.as_tool(tool_name, tool_description)` — маршрут в коде и промпте |
| Трассировка из коробки | Видно «кто что делал» | RunHooks (⚙️→✅ по каждому tool) + локальная трассировка сессий |

| Ось | LangChain | CrewAI | OpenAI SDK |
|---|---|---|---|
| Control flow | Скрыт за цепочками | Скрыт за «экипажем» | Явные handoffs: субагенты = tools |
| Наблюдаемость | LangSmith — **облако** (нарушает NDA) | Самопис | Локально: DebugServer :9100, SQLite, JSONL |
| Роутинг | LLM внутри цепочек | Авто, непредсказуемо | Главный агент сам решает, но через явные tools |

**Подтверждение практикой:** ветка `openai-agents-sdk` — production; три субагента
(rag / code / gitlab) реально работают в проде через `agent.as_tool()`.

**Вывод:** SDK закрыл все три критерия, LangChain и CrewAI — нет.
Это не «первое, что попалось», а скоринг по нашим требованиям.
