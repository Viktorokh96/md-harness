# PRD: CONTROL ROOM (inline-vibe)

## Executive Summary

**CONTROL ROOM** — система древовидного диалога с LLM-агентом через markdown. Пользователь пишет сообщения в ` ```agentsmindmap ` блоке внутри любого `.md` файла, watcher отслеживает изменения через inotify, и AI-агент отвечает, встраивая `🤖` узлы в то же дерево. Пользователь пишет `*` для заметок (mind map без агента) и `*?` для вопросов агенту — препроцессор заменяет их на `👤` и `👤❓` соответственно.

Главная идея: **весь диалог и память — один git-трекаемый markdown-файл**. Никакой базы данных, никакого чат-UI, никакого веб-сервера. Редактор + файл + watcher = минимальный полный интерфейс агента.

Проблема, которую решает продукт: беседа с LLM в плоском чате теряет структуру — параллельные темы смешиваются, история не ветвится, контекст размывается. Древовидный диалог держит каждую тему в своей ветке; `👤`/`👤❓` (пользователь) и `🤖` (агент) — маркеры узлов. `[hide]` и `[archive]` управляют видимостью и размером файла без вызова LLM; `.graph.json` sidecar хранит полное дерево даже поверх скрытых веток.

## Background & Context

Проект вырос из потребности в «лёгком» интерфейсе AI-агента для инженерной работы — код-ревью, архитектурные обсуждения, планирование. Текстовый редактор — основной инструмент разработчика, поэтому интерфейс в виде markdown-файла естественен.

Ключевые инсайты, найденные в процессе разработки:
- **Плоский лог теряет структуру**: в чат-интерфейсе нельзя ответить на сообщение трёхдневной давности, не переключив контекст. Дерево решает это.
- **LLM-вызовы дороги**: `[hide]` и `[archive]` обрабатываются препроцессором — мгновенная реакция, ноль токенов.
- **NDA/локальные модели**: система не зависит от облачных API — любой OpenAI-совместимый эндпоинт, включая локальные модели (qwen, llama, deepseek).

Выбор OpenAI Agents SDK (а не LangChain/CrewAI) задокументирован в [ideas/framework-choice.md](../ideas/framework-choice.md): тонкий слой абстракций, явная маршрутизация handoff'ов, локальная трассировка.

## User Personas

### Разработчик-инженер
- **Кто**: пишет код, обсуждает архитектуру, делает код-ревью
- **Цели**: быстрый доступ к AI-ассистенту без переключения из редактора; структурированные обсуждения сложных тем; история диалога в git
- **Боли**: чат-интерфейсы требуют копипасты кода; контекст теряется между сессиями; параллельные темы смешиваются
- **Сценарий**: открыл `CONTROL_ROOM.md` в редакторе, написал `* Как переписать этот модуль?` — агент прочитал код через `read_file()` и ответил веткой `[*]`

### Технический менеджер/Архитектор
- **Кто**: принимает архитектурные решения, ревьюит дизайн
- **Цели**: видеть цепочку решений; архивировать завершённые обсуждения; искать по истории
- **Боли**: решения теряются в чатах; нет одного источника истины по архитектуре
- **Сценарий**: просматривает дерево в `CONTROL_ROOM.md`, видит свёрнутые `[hide]` ветки, archivирует устаревшие обсуждения

### AI-исследователь/Prototyper
- **Кто**: экспериментирует с агентами, промптами, инструментами
- **Цели**: быстро прототипировать агентное поведение; делегировать подзадачи worker-у
- **Боли**: фреймворки типа LangChain добавляют слишком много абстракций
- **Сценарий**: добавляет новый инструмент в `agent.py`, тестирует через `CONTROL_ROOM_TEST.md --once`

## User Flows

### Основной цикл: пользователь → агент → ответ

```
1. Пользователь открывает CONTROL_ROOM.md в редакторе
2. Добавляет узел: `*? Привет, что можешь сказать об этом проекте?`
3. Сохраняет файл
4. watcher.py обнаруживает изменение (inotify)
5. _sync_graph(): парсинг .md, загрузка .graph.json, merge
   - Если diff состоит только из [hide]/[archive] → шаг 8 (без LLM)
6. compute_diff(old, new) → diff передаётся агенту
7. Агент читает дерево (read_mindmap), анализирует diff, вызывает add_reply()
   - add_reply обновляет .graph.json и перерендеривает .md
8. Готово — пользователь видит ответ в редакторе
```

### Скрытие ветки (без LLM)

```
1. Пользователь добавляет [hide] к узлу:
   `*[hide] Архивное обсуждение`
2. Сохраняет файл
3. watcher обнаруживает изменение
4. _sync_graph: парсит маркер [hide], обновляет .graph.json,
   перерендеривает .md (ветка схлопнута в строку-резюме)
5. LLM НЕ вызывается — время реакции < 1 мс
```

### Архивация ветки

```
1. Пользователь добавляет [archive] к узлу:
   `*[archive: устарело] Старое обсуждение`
2. Сохраняет файл
3. watcher → _sync_graph: парсит маркер
4. archiver.archive_branch():
   - One-shot LLM (не CONTROL ROOM агент!) суммаризирует поддерево
   - Полное поддерево пишется в archive/<node_id>_<timestamp>.md
   - В .md остаётся строка `*[hide] резюме`
   - .graph.json актуализируется (дети удалены)
5. Восстановление: удалить [archive] → restore_branch() из archive/
```

### Альтернативные пути и error states

- **LLM недоступна**: агент возвращает ошибку, пользователь видит сообщение в консоли watcher. Файл не повреждается — изменения ждут следующего прохода.
- **Парсинг сломан** (невалидный markdown): `parse_mindmap()` возвращает пустое дерево или частичный парсинг; агент сообщает о проблеме.
- **Файл удалён во время работы**: watcher логирует ошибку и продолжает вотчить директорию; при создании нового файла — подхватывает.
- **Гонка: пользователь редактирует во время ответа агента**: `_sync_graph()` merge-ит изменения; UUID защищают от потери данных; агент работает с состоянием на момент запуска.

## Non-Functional Requirements

- **Performance**:
  - Парсинг/сериализация: < 10 мс для файла до 10K строк
  - `[hide]`/`[archive]` препроцессинг: < 1 мс (без LLM)
  - Вотчер: реакция на изменение < 100 мс (inotify)
  - LLM-ответ: зависит от модели, не регламентируется системой
- **Security**:
  - API-ключи через `.env` (в `.gitignore`)
  - `read_file()` блокирует выход за пределы project root
  - `run_shell()` ограничен таймаутом (30 с по умолчанию)
  - Трассировка отключена по умолчанию (`DISABLE_TRACING=1`)
- **Compatibility**:
  - Python ≥ 3.14
  - Linux (inotify), macOS (FSEvents), Windows (ReadDirectoryChangesW) — через watchfiles
  - Любой OpenAI-совместимый эндпоинт (OpenAI, DeepSeek, локальные модели через vLLM/LiteLLM)
- **Reliability**:
  - `.graph.json` sidecar гарантирует сохранность скрытых данных
  - `archive/` директория хранит полные поддеревья
  - UUID защищают от коллизий при merge

## Design Decisions (архитектурный контекст)

Задокументированы для будущих контрибьюторов.

1. **Дерево, а не плоский лог**: ветвление диалога ≠ лента сообщений. Стабильные ID узлов (UUID) для адресации.
2. **`.graph.json` sidecar**: `.md` — это VIEW в граф; полное дерево (включая скрытые поддеревья) хранится в JSON. `.md` перерендеривается из графа.
3. **`[hide]` как препроцессор**: никаких LLM-вызовов на toggle видимости. Мгновенно, бесплатно.
4. **UUID вместо ordinal ID**: при merge двух версий файла ordinal ID (`root.1`, `root.1.1`) ломаются; UUID выживают.
5. **7 инструментов, не больше**: каждый инструмент покрывает одну операцию над деревом или средой. Никаких «универсальных» инструментов — агент должен явно выбирать действие.
6. **OpenAI Agents SDK вместо LangChain**: тонкий слой, явный control flow, локальная трассировка. Подробный анализ в [ideas/framework-choice.md](../ideas/framework-choice.md).
7. **Файл — источник истины**: система stateless между проходами. Всё состояние — в `.md` + `.graph.json` + `archive/`. Никакой БД.
8. **`?` — явный триггер агента**: `*` без `?` = режим mind map (пользователь рассуждает сам с собой, агент не вызывается). `*?` = вопрос агенту. Это даёт пользователю полный контроль над тем, когда тратить LLM-токены. После ответа агента `❓` автоматически снимается препроцессором — узел становится обычной заметкой.
